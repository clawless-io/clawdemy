## What you'll learn

This is the eighth lesson in our adaptation of Stanford CME 295: Transformers & Large Language Models. Lesson 7 covered the training that bolts instruction-following onto a base model: supervised fine-tuning teaches the model to respond to instructions, RLHF teaches it which kinds of responses people prefer. Now you have an assistant that wants to follow instructions. This lesson is about how to write the instructions. We'll cover the three prompting patterns that show up everywhere (zero-shot, few-shot, and chain-of-thought), when each one earns its place, when it adds noise, and the structural reason that any instruction-tuned model is vulnerable to prompt injection. Course materials are at [cme295.stanford.edu](https://cme295.stanford.edu/); this lesson draws on the prompting sections of the syllabus.

## Before you start

**Prerequisites:** Lesson 7 (fine-tuning + RLHF) is strongly recommended. The reason prompting works at all is that the model has been trained to interpret an input as an instruction rather than as text to continue. If "instruction-tuned model," "SFT," or "RLHF" feel unfamiliar, read lesson 7 first. Lesson 6 (text generation) is also helpful background, since prompting is ultimately just choosing the input tokens that condition the next-token prediction loop.

## By the end, you'll be able to

- Distinguish zero-shot, few-shot, and chain-of-thought prompting and identify which pattern a given prompt uses
- Explain why few-shot prompting works (in-context learning) and where it stops scaling
- Recognize task types where chain-of-thought helps versus task types where it adds noise without improving accuracy
- Identify a prompt-injection attempt and explain why instruction-tuned models are structurally vulnerable to it
