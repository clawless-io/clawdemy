## The one idea that matters

```
pretraining (trillions)  →  SFT (tens of thousands)  →  RLHF (hundreds of thousands)
       (knows)                  (follows)                    (has taste)
```

## The three-stage pipeline

| Stage | Data (typical) | Objective | Output | Time |
| --- | --- | --- | --- | --- |
| 1. Pretraining | Trillions of tokens of unfiltered web text | Next-token prediction | Base model | Months on a cluster |
| 2. Supervised fine-tuning (SFT) | Tens of thousands of curated instruction-response pairs | Imitate the responses | Instruction-tuned model | Days |
| 3. RLHF | Hundreds of thousands of human preference comparisons | Maximize a learned reward | Chat assistant | Days, plus a separate reward model |

## RLHF in two parts

| Part | Input | Process | Output |
| --- | --- | --- | --- |
| 1. Reward model | Human preference comparisons (`prompt`, `response_A`, `response_B`, `picked`) | Train a model to predict the human pick as a scalar score | Reward model that scores `(prompt, response)` |
| 2. Policy optimization | SFT model (the policy) and the reward model | Policy generates response, reward model scores, RL algorithm (commonly PPO) nudges policy weights toward higher-scoring responses; a KL-style regularization penalty tethers the policy to the SFT model to prevent reward hacking | Chat assistant |

## Modern variants

| Approach | What changes vs canonical RLHF |
| --- | --- |
| **DPO** (Direct Preference Optimization) | Skips the separate reward model; optimizes the SFT model directly on preference data. Simpler pipeline, often comparable quality, increasingly popular in open-source. |
| **CAI** (Constitutional AI) | Some human comparisons replaced by AI-generated critiques working from a written set of principles. Reduces labeling burden; introduces critic-bias risk. |
| **RLAIF** (RL from AI Feedback) | Umbrella term for using AI rather than human comparisons during the preference-learning step. |

## Which observable behavior comes from which stage

| Observable behavior | Primary stage | Notes |
| --- | --- | --- |
| Knows facts about the world | Pretraining | Knowledge encoded in weights from reading text |
| Follows an instruction at all | SFT | Base model would continue the prompt as text |
| Polished, structured, polite tone | RLHF (SFT seeds) | Format often present in SFT, RLHF reinforces |
| Refuses harmful or out-of-scope requests | RLHF | Refusals were labeled as preferred during preference training |
| Self-identifies with a product persona | SFT + RLHF | System prompt examples in SFT; persona reinforcement in RLHF |
| Style / personality changes between releases | New SFT + new RLHF | Architecture rarely changes between releases; post-training does |

## Pitfalls to dodge

| Pitfall | Reality |
| --- | --- |
| SFT teaches new knowledge | No. SFT teaches response shape. Knowledge was in the base model from pretraining. |
| RLHF gives a model "values" | No. RLHF gives preferences toward responses the reward model rates highly. The reward model captures labelers' picks, not philosophical commitments. |
| Fine-tuning equals RLHF | No. Fine-tuning is the umbrella; SFT is one kind. RLHF builds on SFT by adding reward modeling and policy optimization. |
| Reward model output equals truth | No. The reward model scores responses the way labelers would. It is a proxy for helpfulness, not a guarantee of factual accuracy or calibrated uncertainty. |
| The assistant has a fixed personality | No. Same base model can be post-trained in different directions to produce assistants that feel very different. The base is the same; post-training shapes the personality. |

## Translating model release language

| Vendor claim | What it usually means |
| --- | --- |
| "We retrained the assistant" | New SFT data plus new RLHF preferences. Days, not months. |
| "We improved safety" | New refusal labels in the preference data; reward model now scores those refusals higher. |
| "We released a base model / instruction-tuned model" | Stage 1 only, or stages 1 and 2. Stage 3 (RLHF) adds the polish you associate with chat assistants. |

## Glossary

- **Base model:** the output of pretraining. Predicts next tokens; does not follow instructions.
- **SFT (supervised fine-tuning):** trains the base model on curated instruction-response examples using next-token prediction.
- **Instruction-tuned model:** the post-SFT, pre-RLHF model. Follows instructions; has no preference among valid responses.
- **RLHF (reinforcement learning from human feedback):** uses a learned reward model trained on human preference data to optimize the SFT model.
- **Reward model:** a separate model that scores `(prompt, response)` pairs; trained to predict human preferences.
- **Policy:** in RL terminology, the model being optimized; in RLHF, the SFT model.
- **PPO (Proximal Policy Optimization):** the RL algorithm commonly used to update the policy against the reward model.
- **Reward hacking:** the policy finding ways to score high on the reward model without actually being helpful, prevented by KL regularization.
- **KL penalty / regularization:** a term in the RLHF loss that keeps the policy close to the SFT model, preventing reward hacking.
- **DPO (Direct Preference Optimization):** an alternative to canonical RLHF that skips the separate reward model and optimizes the SFT model directly on preference data.
- **CAI (Constitutional AI):** an approach that replaces some human comparisons with AI-generated critiques based on written principles.
- **RLAIF (Reinforcement Learning from AI Feedback):** umbrella term for using AI rather than humans for preference data.
- **Preference data:** pairs of model responses ranked by human (or AI) labelers. The raw input to the reward model.
- **Post-training:** any training stage after pretraining. SFT and RLHF are both post-training.

**Pretraining gives the model knowledge.**\
**Fine-tuning gives it instructions.**\
**RLHF gives it taste.**
