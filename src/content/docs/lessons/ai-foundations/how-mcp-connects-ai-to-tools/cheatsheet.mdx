## The one idea that matters

```
MCP (Model Context Protocol) is a standard plug between AI apps and tools.
It does not make the model smarter. It makes tools reachable.
Build one server; any app that speaks MCP can connect.
```

## Before and after

| | Without a standard | With MCP |
| --- | --- | --- |
| **How a tool reaches an app** | Wired separately for each model or app | One server, many MCP-speaking apps |
| **Who builds the connection** | Each app's developer, again and again | The tool maker, once |

The lecturer calls the old way repeated work to avoid. The official documentation compares MCP to a USB-C port.

## The three roles

| Role | What it is | Example |
| --- | --- | --- |
| **Host** | The AI app you use | A chat assistant, a code editor with AI features, a company chatbot |
| **Client** | Piece inside the host; holds one connection to one server | The host creates one client per server |
| **Server** | Program that offers capabilities | A book provider's server; Playwright MCP |

**Where servers run.** On your own machine, or somewhere on the internet.

## The flow, in the function-calling stages

```
CLIENT asks SERVER: which tools do you have?
HOST hands the tool list to the MODEL
MODEL picks a tool and arguments        (Stage 1, as before)
CLIENT sends the call -> SERVER runs it (Stage 2, now in a server)
Result goes back into the conversation
MODEL writes the answer                 (Stage 3, as before)
```

**The model never talks to the server.** It reads and writes text; the client carries the call and the result.

## What a server offers

| Offering | What it is | Who controls it | Examples |
| --- | --- | --- | --- |
| **Tools** | Actions | The model | Search flights, send a message |
| **Resources** | Read-only data | The app | File contents, database records |
| **Prompts** | Reusable templates that instruct the model | The user | A template showing how to look up a particular title |

**Memory hook:** the model chooses tools, the app manages resources, the user picks prompts.

## The lecturer's example: a poetry book for the teddy bear

| Part | In the example |
| --- | --- |
| Host | The AI chat app |
| Server | Built by a book provider (experts at serving that content) |
| Tools | Find books, recommend books |
| Prompts | How to look up a particular title; recommend to suit a reader's taste |
| Resources | The bear's personal collection; popular books that people buy |

## Playwright MCP: who does what

| Piece | Job |
| --- | --- |
| **Playwright** | Browser automation software; programmers drive it with code |
| **Playwright MCP** | An MCP server built on Playwright, published by the Playwright project |
| **MCP** | The connection: list tools, send calls, return results |
| **The model** | Picks the next step (go to an address, take a snapshot, click) and reads the outcome |
| **What comes back** | A structured text description of the page (an accessibility snapshot), not a screenshot |

**Also true:** the Playwright MCP documentation points coding agents to a command-line route it says uses less of the model's context. MCP is a standard way to connect, not the only way.

## Before you connect a server

| Ask | Why |
| --- | --- |
| Who built it, and do I trust them? | A tool's own description is only as trustworthy as its server |
| What can it reach? | A server on your machine may have direct access to your system |
| Which tools can change things? | Tools can run arbitrary code |
| Will my app ask before each action? | The specification says the host app must get your explicit permission before running a tool; apps can let you approve some actions ahead of time, and MCP cannot enforce any of this itself |

**Playwright MCP's own line:** "Playwright MCP is not a security boundary."

## Pitfalls to dodge

| Pitfall | Reality |
| --- | --- |
| "MCP is a tool." | MCP is the connection. A server wraps a system and offers its actions as tools. |
| "The model talks to the server." | The client does. The model reads and writes text. |
| "MCP belongs to one product." | It came from the Anthropic team, per the lecturer; the docs describe an open-source standard supported by apps from several companies. |
| "More servers is always better." | Each server is more software with access. Connect what you need. |

## Glossary

- **MCP (Model Context Protocol):** an open standard for connecting AI apps to outside tools and data.
- **Protocol:** an agreed set of rules for how two pieces of software talk.
- **Host:** the AI application the user works in.
- **Client:** the piece inside the host that holds one connection to one server.
- **Server:** a program that offers tools, resources, and prompts to AI apps.
- **Local server / remote server:** a server running on your own machine, or one running somewhere on the internet.
- **Accessibility snapshot:** in Playwright MCP, a structured text description of a web page, with a reference for each element.

**MCP does not make the model smarter. It makes tools reachable.**\
**The model asks, the client carries, the server acts.**\
**Plug in only what you trust.**
