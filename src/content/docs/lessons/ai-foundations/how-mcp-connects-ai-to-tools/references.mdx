## Original sources

The official documentation behind every MCP claim in the lesson that is not attributed to the lecturer. These addresses redirect to the current versioned pages of the documentation.

- **[What is the Model Context Protocol (MCP)?](https://modelcontextprotocol.io/docs/getting-started/intro)**, the official introduction. Source for MCP as an open-source standard linking AI apps with outside systems, the USB-C comparison, the example uses (calendars, note-taking workspaces, databases, design files), and the statement that many different apps support MCP. Start here.

- **[Architecture overview](https://modelcontextprotocol.io/docs/learn/architecture)**. Source for the host, client, and server roles, the one-client-per-server rule, local versus remote servers, the three server primitives, the list-then-call flow (a client lists tools, gives them to the model, and runs the ones the model calls), and the note that MCP covers context exchange without dictating how an app uses its model. Read this if you want the next level of detail.

- **[Understanding MCP servers](https://modelcontextprotocol.io/docs/learn/server-concepts)**. Source for the tools, resources, and prompts definitions and for who controls each (model, application, user). Its travel-planning example shows all three working together.

- **[MCP specification overview](https://modelcontextprotocol.io/specification/latest)**, section "Security and Trust & Safety." Source for the lesson's safety claims and its one quoted sentence on tool safety: hosts must get the user's explicit permission before running a tool, users should know what a tool does before allowing it, a tool's own description should not be trusted unless its server is, and the protocol cannot enforce any of this by itself.

- **[Security Best Practices](https://modelcontextprotocol.io/specification/latest/basic/security_best_practices)**, section "Local MCP Server Compromise." Source for the point that a server on your own machine may have direct access to your system. The rest of the page is written for implementers and goes well beyond this lesson.

- **[Playwright MCP](https://github.com/microsoft/playwright-mcp)**, the project's official README. Source for what Playwright MCP is (an MCP server providing browser automation through Playwright, using structured accessibility snapshots rather than screenshots), its tool list (navigate, snapshot, click, and more), the note on the command-line route for coding agents, and the line "Playwright MCP is not a security boundary."

- **[Playwright](https://playwright.dev/)**, the project's home page. Source for the quoted one-line description of Playwright, the languages it supports, and the fact that the Playwright project lists Playwright MCP among its own products.

## Going deeper

- **[Understanding MCP clients](https://modelcontextprotocol.io/docs/learn/client-concepts)**. The other side of the connection: what a client can offer a server, such as asking the user for more information mid-task. Useful once the three roles feel solid.

- **[The MCP specification](https://modelcontextprotocol.io/specification/latest)**. The full requirements for anyone building a client or server. Dense, and written for developers, but the overview page is readable and is where the safety principles live.

- **[MCP reference servers](https://github.com/modelcontextprotocol/servers)**. Example servers maintained by the MCP project, linked from the architecture overview. Browsing the list is a quick way to see what kinds of systems people put the standard plug on.
