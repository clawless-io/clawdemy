## What you'll learn

This is the first lesson in our adaptation of Stanford CME 295 Lecture 7 (Agentic LLMs). The earlier lessons in this track covered how the transformer works (Lecture 1), how it generates text and how to prompt it (Lecture 3), and how it was trained to follow instructions (Lecture 5). This lesson covers how to give the trained model knowledge it does not already have, in the right shape, at the right moment. We'll walk through **retrieval-augmented generation** (RAG), the canonical pattern for grounding a language model in fresh, private, or domain-specific information without retraining it. The lesson walks through the pipeline stage by stage (chunking, embedding, vector search, prompt construction, grounded generation), names the failure mode for each stage, and closes on **indirect prompt injection**, the structural security issue RAG introduces. Course materials are at [cme295.stanford.edu](https://cme295.stanford.edu/).

## Before you start

**Prerequisites:** the prompting lesson (Lecture 3) is required reading. RAG is prompting plus retrieval; if you cannot read a prompt and identify what is doing the work in it, the RAG flow will not make sense. The embeddings lesson (Lecture 1) is also strongly recommended, since vector search uses the same embedding mechanics covered there. The fine-tuning + RLHF lesson (Lecture 5) is helpful background for understanding why RAG is often the right alternative to fine-tuning.

## By the end, you'll be able to

- Explain what RAG is and the three problems it solves (knowledge cutoff, private data, hallucination grounding)
- Walk through the canonical RAG pipeline (chunking, embedding, retrieval, prompt construction, generation) and identify the role of each stage
- Name the failure modes specific to each stage (bad chunk boundaries, weak embeddings, retrieval misses, prompt overflow, ungrounded generation)
- Recognize indirect prompt injection as the structural security issue RAG introduces, and explain why it is harder to defend against than direct injection

## Time and difficulty

- **Read time:** about 25 minutes
- **Practice time:** about 15 minutes (a pipeline-tracing exercise: walk a query through each RAG stage and predict where it would fail)
- **Difficulty:** standard
