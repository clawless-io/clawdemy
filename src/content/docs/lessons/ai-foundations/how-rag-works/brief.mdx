## What you'll learn

This is the ninth lesson in our adaptation of Stanford CME 295: Transformers & Large Language Models. Lesson 8 covered how to talk to an instruction-tuned model. This lesson covers how to give it knowledge it does not already have, in the right shape, at the right moment. We'll walk through **retrieval-augmented generation** (RAG), the canonical pattern for grounding a language model in fresh, private, or domain-specific information without retraining it. The lesson walks through the pipeline stage by stage (chunking, embedding, vector search, prompt construction, grounded generation), names the failure mode for each stage, and closes on **indirect prompt injection**, the structural security issue RAG introduces. Course materials are at [cme295.stanford.edu](https://cme295.stanford.edu/); this lesson draws on the applications sections of the syllabus.

## Before you start

**Prerequisites:** Lesson 8 (prompting) is required reading. RAG is prompting plus retrieval; if you cannot read a prompt and identify what is doing the work in it, the RAG flow will not make sense. Lesson 3 (embeddings) is also strongly recommended, since vector search uses the same embedding mechanics covered there. Lesson 7 (fine-tuning + RLHF) is helpful background for understanding why RAG is often the right alternative to fine-tuning.

## By the end, you'll be able to

- Explain what RAG is and the three problems it solves (knowledge cutoff, private data, hallucination grounding)
- Walk through the canonical RAG pipeline (chunking, embedding, retrieval, prompt construction, generation) and identify the role of each stage
- Name the failure modes specific to each stage (bad chunk boundaries, weak embeddings, retrieval misses, prompt overflow, ungrounded generation)
- Recognize indirect prompt injection as the structural security issue RAG introduces, and explain why it is harder to defend against than direct injection

## Time and difficulty

- **Read time:** about 25 minutes
- **Practice time:** about 15 minutes (a pipeline-tracing exercise: walk a query through each RAG stage and predict where it would fail)
- **Difficulty:** standard
