## What you'll learn

This is a lesson in Phase 6, *How models reason and act*, in Track 5 (AI Foundations). The earlier lessons covered how the transformer works (Phase 2), how it generates text and how to prompt it (Phase 5), and how it was trained to follow instructions (Phase 4). This lesson covers how to give the trained model knowledge it does not already have, in the right shape, at the right moment. We'll walk through **retrieval-augmented generation** (RAG), the canonical pattern for grounding a language model in fresh, private, or domain-specific information without retraining it. The lesson walks through the pipeline stage by stage (chunking, embedding, vector search, prompt construction, grounded generation), names the failure mode for each stage, and closes on **indirect prompt injection**, the structural security issue RAG introduces. Course materials are at [cme295.stanford.edu](https://cme295.stanford.edu/).

## Where this fits

This is a lesson in Phase 6, *How models reason and act*. Phase 5 covered inference-time steering (generation loop, prompting). This lesson adds retrieval: how to augment a prompt with fresh or private information the model was not trained on. It builds directly on the prompting lesson and the embeddings lesson (vector search is embedding lookup with a retrieval step on top).

## Before you start

**Prerequisites:** the [prompting lesson](/lessons/ai-foundations/how-prompting-works/lesson/) and the [embeddings lesson](/lessons/ai-foundations/how-words-become-vectors/lesson/) are required. RAG is prompting plus retrieval; if you cannot read a prompt and identify what is doing the work in it, the RAG flow will not make sense. Vector search uses the same embedding mechanics covered in the embeddings lesson. Phase 4 (fine-tuning and RLHF) is helpful background for understanding why RAG is often the right alternative to fine-tuning, but is not required.

## By the end, you'll be able to

- Explain what RAG is and the three problems it solves (knowledge cutoff, private data, hallucination grounding)
- Walk through the canonical RAG pipeline (chunking, embedding, retrieval, prompt construction, generation) and identify the role of each stage
- Name the failure modes specific to each stage (bad chunk boundaries, weak embeddings, retrieval misses, prompt overflow, ungrounded generation)
- Recognize indirect prompt injection as the structural security issue RAG introduces, and explain why it is harder to defend against than direct injection

## Time and difficulty

- **Read time:** about 25 minutes
- **Practice time:** about 15 minutes (a pipeline-tracing exercise: walk a query through each RAG stage and predict where it would fail)
- **Difficulty:** standard
