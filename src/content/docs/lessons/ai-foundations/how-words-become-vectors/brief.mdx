## What you'll learn

This is the second lesson in our adaptation of Stanford CME 295 Lecture 1 (Transformer). The full course materials (syllabus, schedule, the Amidi cheatsheets) are at [cme295.stanford.edu](https://cme295.stanford.edu/). The previous lesson covered tokenization, the bridge from raw text to integer IDs. But a token ID is just a number with no meaning attached, so how does the model know that "king" is closer in meaning to "queen" than to "banana"? The answer is embeddings: dense vectors that take the place of token IDs and carry meaning into the model. We'll build the intuition (words as points on a map), walk through the lookup table that stores them, see "king minus man plus woman" land near "queen" as actual vector arithmetic, and land on why every modern semantic-search and retrieval-augmented system in production runs on this idea.

## Before you start

**Prerequisites:** the previous lesson (tokens) is a useful companion but not required; we recap what a token ID is in the body of the lesson. Some basic intuition for what a vector is (a list of numbers, or a direction in space) helps. If "vector" is unfamiliar, the first episode of [3Blue1Brown's Essence of Linear Algebra](https://www.youtube.com/playlist?list=PLZHQObOWTQDPD3MizzM2xVFitgF8hE_ab) (about 10 minutes) is the gentlest entry point.

## By the end, you'll be able to

- Explain why integer token IDs alone are not enough for the model and why dense vectors are the next step
- Describe the embedding lookup table as a `vocab_size` by `embedding_dim` matrix where each row is one token's vector
- Demonstrate how vector arithmetic captures semantic relationships, using the canonical "king - man + woman ≈ queen" example
- Connect embeddings to real-world AI applications, including vector search and retrieval-augmented generation
