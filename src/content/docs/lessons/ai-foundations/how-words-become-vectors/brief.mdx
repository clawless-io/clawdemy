## What you'll learn

This is lesson 2 of Phase 1, *How models read text*, in Track 5 (AI Foundations). The Stanford CME 295 course materials (syllabus, schedule, the Amidi cheatsheets) are at [cme295.stanford.edu](https://cme295.stanford.edu/). The previous lesson covered tokenization, the bridge from raw text to integer IDs. But a token ID is just a number with no meaning attached, so how does the model know that "king" is closer in meaning to "queen" than to "banana"? The answer is embeddings: dense vectors that take the place of token IDs and carry meaning into the model. We'll build the intuition (words as points on a map), walk through the lookup table that stores them, see "king minus man plus woman" land near "queen" as actual vector arithmetic, and land on why every modern semantic-search and retrieval-augmented system in production runs on this idea.

## Where this fits

This is lesson 2 of Phase 1, *How models read text*. The previous lesson covered tokenization (how raw text becomes token IDs). This lesson covers the next step: how those token IDs become dense vectors that carry semantic meaning. The next lesson in the phase is *How models know word order*, which adds positional information to the vectors this lesson produces. Together, all three Phase 1 lessons trace a sentence from raw text into the sequence of dense, position-aware vectors the model actually operates on.

## Before you start

**Prerequisites:** the [tokenization lesson](/lessons/ai-foundations/how-ai-reads-tokens/lesson/) is the recommended starting point for Track 5; we briefly recap what a token ID is in the body of this lesson, but the tokens lesson gives the fuller picture. Some basic intuition for what a vector is (a list of numbers, or a direction in space) helps. If "vector" is unfamiliar, the first episode of [3Blue1Brown's Essence of Linear Algebra](https://www.youtube.com/playlist?list=PLZHQObOWTQDPD3MizzM2xVFitgF8hE_ab) (about 10 minutes) is the gentlest entry point.

## By the end, you'll be able to

- Explain why integer token IDs alone are not enough for the model and why dense vectors are the next step
- Describe the embedding lookup table as a `vocab_size` by `embedding_dim` matrix where each row is one token's vector
- Demonstrate how vector arithmetic captures semantic relationships, using the canonical "king - man + woman ≈ queen" example
- Connect embeddings to real-world AI applications, including vector search and retrieval-augmented generation
