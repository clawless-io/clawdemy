## The CostGuard mental model

A software safety net that tracks your BYOK spend against a monthly cap. Warns when you cross a threshold, blocks new sends at 100% (default). With Block on, it can stop what Clawless Computer itself starts (checked when work starts, so a run under way can finish); some engine-run work counts but cannot be stopped, and some spending is not counted at all (see below).

## The three settings (Settings, Budget)

| Setting | Options | Default |
| --- | --- | --- |
| Monthly cap | $0 (unlimited), $5, $10, $25, $50, $100, custom | Pick what feels comfortable |
| Warn threshold | 50%, 80%, 90%, off | 80% |
| Hard-stop behavior | Block new messages, Warn-and-allow | Block |

## What counts toward the cap

| Usage type | Counts? | Why |
| --- | --- | --- |
| Pay-as-you-go API keys (Anthropic, Google AI, Groq, OpenAI, most others) | Yes | Per-token billing on your provider account; CostGuard sums it |
| Local models (running on your computer, for example through Ollama or LM Studio) | No | Free; shown as "Local, free" |
| Models whose price is not known (custom setups without a price, some new models) | No | Shown as "Price not known"; your provider still bills you. With Block on, Clawless Computer asks before sending most messages to them |
| Image generation | No | No per-picture prices yet; each picture is billed to that provider's account. The chat around it is counted |

The cap counts what Clawless Computer can put a price on.

## What the cap can stop

| Can stop (Clawless Computer starts it) | Counts, but cannot stop while it runs (runs inside the engine) |
| --- | --- |
| What you type in the chat box | Replies in a connected channel (Telegram, Discord, Slack and others) |
| "Run now" on a scheduled job | Scheduled jobs running on their schedule |
| Compacting a conversation | Turns an agent starts by itself, such as a sub-agent |
| Allowing an action when the agent asks "Allow this action?" | |
| The app's own background work, such as sorting new memories | |

Saying no to an action always goes through, even over the cap. If you use channels or scheduled jobs, watch the Usage dashboard and pause them near your cap.

**The engine control page (off unless you turn it on under Settings, Security).** If you turn it on, the spending limit does not apply to what you do on that page. That page talks straight to the engine, so the checks Clawless Computer puts in front of it (the spending limit, the settings confirmations, and the link and picture locks) stop applying there.

## The two visual cues

| State | Indicator | Behavior |
| --- | --- | --- |
| Under warn threshold | Dock row indicator neutral | Send freely |
| At warn threshold (80% by default) | Dock row indicator yellow + one-time notification | Send still works; quiet visual signal |
| At 100% cap | Dock row indicator red | With Block on (default): next send rejected, banner appears in chat. With Warn-and-allow: every send warns but goes through |

The hard-cap banner reads:

```text
Monthly budget reached. Bump your cap in Settings to keep going.
```

## Unblocking once you hit the cap

| Path | What it does |
| --- | --- |
| Raise the cap in Settings, Budget | Unblocks immediately on save |
| Wait for the period to reset | Default rolling 30-day window: oldest day's spend ages out today. Alternative: calendar-month resets (matches monthly subscription billing) |

## Habits that compound to lower cost

| Habit | Why it works |
| --- | --- |
| Pick the right model for the task | Heavyweight models cost 5x to 10x what smaller ones do per token |
| Fresh conversation when topic changes | Long threads carry full history with every new message; cost grows linearly with length |
| Watch the Usage dashboard weekly | Breaks spend down by provider, model, session, and day; one specific session sometimes ate everything, and that tells you what to change |

## The data path (one message, end to end)

```
your keyboard
     v
the Clawless Computer app on your computer
     v
OpenClaw engine (still on your computer)
     v
the AI provider over the internet  <-- the only server in the path
     v
OpenClaw
     v
Clawless Computer
     v
your screen
```

**No [Clawless Computer](https://clawless.ai) server in the data path.** Path is: your computer, the AI provider, your computer.

## Where your stuff lives

| Place | What lives there | Who can read it |
| --- | --- | --- |
| Your computer, in one data folder (Settings, then System, then Your data) | API keys, conversations, memories, agent definitions, settings. The OpenClaw engine stores API keys there, not encrypted; Clawless Computer never shows a saved key. For stronger at-rest protection, turn on FileVault on a Mac or BitLocker on Windows | Your user account, and tools the assistant runs as your account |
| AI provider servers | Your message and the memories that travel with it | The provider, per their terms; most default to not training on API customer data, but read the terms |

Other connections (the skill catalog when you open or search it, add-on downloads when you set up a channel, update checks when you ask) carry none of your conversations, memories, or API keys. Channels and tools you set up contact those services on your behalf. Clawless Computer adds no telemetry, analytics, or crash reporting. There is no license server and no account.

## The four-party trust model

| You trust | With what |
| --- | --- |
| Us | The desktop app does what it claims; local data protected to the standards your operating system supports |
| The AI provider you picked | The contents of your messages and the memories that travel with them |
| OpenClaw (open-source engine) | Being a faithful intermediary; the code is open for you to audit |
| Any tool, skill, or integration you install | The permissions it asks for, same model as browser extensions |

## Two projects, two licences

- **Clawless Computer: GNU AGPL v3.** The desktop app, the chrome around the engine. Free software; Settings, About links to its source code on GitHub.
- **OpenClaw: MIT.** The engine bundled inside Clawless Computer that talks to providers. A separate open-source project.

They are not the same project. The data path crosses both. Both can be audited from their source.

## If Clawless Computer went away tomorrow

| What | Status |
| --- | --- |
| Your conversations, memories, settings, agent definitions, API keys | Still on your computer. They do not vanish when the company does. |
| New app updates | Stop. |
| License check | None. There is no license server and no account, so nothing locks you out. |
| Local models | Keep working offline, no cloud needed. The strongest version of the no-cloud guarantee. |

## Pitfalls to dodge

- Setting a cap so high it never trips (you learn nothing about your usage shape)
- Assuming the cap stops channel replies and scheduled jobs (they count, but run inside the engine; pause them yourself near the cap)
- Assuming image generation or a "Price not known" model counts toward the cap (neither does; your provider still bills you)
- Treating Warn-and-allow as the safe default (Block is safer; Warn-and-allow is for specific reasons)
- Comparing the Usage dashboard to the provider's invoice down to the cent (close match expected; if there is a discrepancy, the provider's bill is the legal truth, ours is a real-time tracking signal)
- Assuming there is a cloud you can sign into from a second device (there is not; local-first trades cross-device sync for the no-cloud guarantee)

## Worth opening once

The **Usage dashboard**, weekly for the first month. Look for the one session that ate disproportionate budget. That is the most important number on the screen.
