You finished lesson 1 with one task in mind. The one you decided was worth handing to AI.

This is the lesson where you actually hand it to AI.

This lesson's practice is written for [Clawless Computer](https://clawless.ai), the free desktop home for OpenClaw that we build alongside Clawdemy. Picture it open in front of you, with onboarding done and at least one provider key saved. There is a window, and inside the window there is a chat waiting for you to type. The whole rest of the track sits on top of this one capability: send a message, get a reply, decide which model handled it. Once that loop is real to you, the rest of Clawless Computer is just additions to it.

The lesson takes about eleven minutes to read and ten minutes to do at the same time. You can read first and then try, or read with Clawless Computer open and try as you go. Either is fine.

## What you are looking at

When you land in Clawless Computer after onboarding, the window has three main areas.

Down the left side there is a vertical list of avatars. That is the agent rail. Each avatar is a different agent, each one set up for a different kind of work. The one to start with is called Assistant, which is exactly what it sounds like, the friendly default to use when you do not know who else to ask. The Agents and Overview chapter of the Clawless Computer help docs introduces the other agents and when to reach for which.

The middle of the window is the chat. It has four parts: the header, the message area, a row of controls, and the message box. The header at the top shows the agent's avatar, the conversation title, and the current model. The message area in the middle holds the conversation; in a fresh chat it shows a small grid of suggested prompts until you send something. The message box at the bottom is where you type.

Above the message box there is a row of controls. In order, it holds a New conversation button, the connection status, and the model picker, then a few more controls, including Skills, Tools and Commands, and on the right, today's cost and Feedback. The one that matters most for this lesson is the model picker. It shows the current model's name. We come back to it in a minute.

Far left, the narrow strip of icons is the navigation rail. Those icons open the panels for Tools, Skills, Memory, Channels, Cron, Logs, Usage, and Settings. You do not need any of them for this lesson.

That is the whole tour. Three areas: the agent rail on the left, the chat in the middle, and the navigation rail at the far left. Inside the chat, four parts: header, message area, the row of controls, and the message box.

## Send your first message

Click into the input box at the bottom of the chat. Type the question you brought from lesson 1.

If you did not bring one, type this:

> Help me write a short status update to my team about a project that is on track but had two small blockers this week. Keep it three sentences. Confident tone.

Press Enter. If you want a new line instead of sending, press Shift and Enter together.

Two things happen. Below your message, a short status line appears: "Thinking", "Reading file", or something similar. That is the activity indicator; it tells you what the agent is doing in real time. Then the agent's reply starts to stream in word by word. You do not have to wait for the whole reply before you start reading.

If the reply is heading somewhere you do not want, you can stop it. Where the Send button used to be, you will now see a square icon. That is the Stop button. Press it and the agent stops streaming, and the chat shows a short "Stopped." line.

If the engine takes a few seconds to catch the stop request, you will see a small "Stopping..." line. If after about fifteen seconds it has still not stopped, a red banner with a Force Stop button appears. Use Force Stop only as a last resort. It only stops the app waiting. The reply may keep running at the provider for a while, and the provider may keep billing for it.

One more thing about replies. Moving to another chat or another agent does not stop a reply in progress. The agent keeps working, and a small pulsing dot shows it. Come back to that chat and the reply is there.

When the reply finishes, code blocks have a Copy button in the corner, tables render as real tables, links are clickable. You read the reply, and if you have a follow-up you type it into the input box and press Enter again. The agent remembers everything in the current conversation, so you do not have to re-paste context every time.

## The model picker

Find the chip with the current model's name on it, in the row of controls above the message box.

That is the model picker. Click it.

A short list opens, grouped by provider. It shows models from the providers you saved a key for, plus a model server running on your own computer if you have one. Each model shows its provider right next to its name, because the same model can be offered by more than one provider. New chats start with your default model, which is first set from the provider whose key you saved first.

Two things are worth knowing about the list.

First, it is a curated short list, not the full catalog of every model every provider ships. Most providers have dozens of models, and most of the differences between them are not worth thinking about for most of the work you will do. The list shows what the Clawless Computer team recommends. The default short list is enough for almost everything.

Second, if the model you want is not on the short list, you can still use it. The picker also accepts a provider-prefixed name typed straight into it. The format is the provider's short name (like openai), a slash, and the model name. The help docs give an example, shown below.

```text
openai/gpt-5.4-mini
```

Type that pattern (the provider's short name, then a slash, then the model name) into the picker and Clawless Computer uses that model even if it is not on the visible short list. It only works for a provider the picker offers. You only need to do this when you have a specific reason; for the first dozen conversations, just pick something from the short list.

The default rule of thumb when you are starting out: start with the default; reach for a bigger model when a task is hard. Lesson 3 of Track 22 ("Choosing your model and the effort dial") goes into the cost-and-capability arithmetic in detail; the short version is that smaller models usually cost much less, and after a few conversations you will start to notice which tasks the small models handle fine and which need the big ones.

## Switch models in the middle of a conversation

This is the load-bearing feature of the picker and it is worth a section of its own.

You can switch models at any point in a conversation. The new model picks up where the previous one left off; it sees the whole conversation history and continues. There is no rule that says "this conversation is locked to one model."

A model you pick inside a chat applies to that chat only. It does not change the model your new chats start with. That default lives in Settings, under API Keys, in the setting called "Default model for new chats". Agents that have no model of their own use it too.

Here is when switching matters in practice.

You ask a hard question that benefits from a heavyweight model. You let one of the big models draft a careful answer. Then you have ten small follow-ups about the draft, none of them as hard as the first question. You switch to a smaller, cheaper model for the follow-ups. The conversation continues as if nothing happened, and each follow-up costs less.

The reverse also works. You start with a small fast model for an easy task. Halfway through, the task gets harder than you expected. You switch to a bigger model and the conversation continues. The hard part gets the right tool.

Costs follow the model you are using at the moment you send each message. Switching does not retroactively cost anything; it just changes the meter going forward. That is the whole rule.

## What happens when you switch agents

Each agent has its own preferred model. When you click a different agent on the left rail, the model picker updates to that agent's preferred model. This is not a glitch; it is intentional. The Researcher agent may want a different model than the Writer agent.

You can still pick a different model for the current conversation in the picker. If you want to change an agent's preferred model permanently, you edit the agent itself; the Agents and Overview chapter of the help docs covers how.

The other thing worth knowing is that each agent keeps its own conversation history. When you click between agents, you do not lose your place in either; you swap between two parallel conversations. That makes it easy to run a quick task on the Assistant while a longer Researcher reply is still being written in the background.

## A few small things you will notice

The model name in the conversation header (the very top of the chat area) shows the current model. If you switch models mid-conversation, the header reflects the model you have selected.

The Usage panel, on the navigation rail at the far left, breaks down costs by model and by conversation (the Models and Sessions tabs). After your first few conversations it is worth opening once just to see what each model costs you in practice. Reading is more durable than guessing.

Slash commands are a power-user shortcut you can ignore for now. Typing a forward slash at the start of the input opens a small menu of commands, including one to switch this conversation's model without leaving the keyboard. You do not need them for the first hour with Clawless Computer. The Chat and Models chapter of the help docs lists them when you are ready.

## Common first-day surprises

Four things people often notice on the first day. Knowing them in advance saves frustration.

1. **The first message of a session feels slow.** The engine warms up on the first message, and the AI provider sometimes has a cold-start delay on its end. Every later message in the same session is faster. This is normal.

2. **A small status indicator appears below your message while the agent thinks.** That is the activity indicator, not a problem. It tells you what is happening: thinking, reading a file, searching the web, calling a tool. If you ever wonder whether the agent is stuck, the activity indicator is your answer.

3. **Switching to a different agent loads a different conversation, not a continuation of the current one.** Each agent has its own thread. That is the right design for handing different kinds of work to different specialists, but it surprises people on the first day. If you want to continue the current topic, do not switch agents; keep going in the same one.

4. **The model picker shows different defaults for different agents.** Each agent has its own preferred model. Clicking between agents looks like the picker is randomly changing; it is not. The picker is following the agent.

## What you should remember

- **Your first message is just typing and pressing Enter.** The chat from top to bottom is header, message area, the row of controls, the message box. The model picker is the chip with the model's name, in the row of controls above the message box.
- **The model picker is a curated short list grouped by provider, drawn from the providers you saved a key for.** Each model shows its provider by name. If you need an off-list model, type the provider-prefixed name into the picker.
- **You can switch models mid-conversation, and the new model continues where the previous one left off.** A pick inside a chat changes only that chat; the default for new chats lives in Settings, API Keys. The cost meter follows the model you are using at the moment you send each message.
- **Each agent has its own preferred model and its own conversation history.** Switching agents swaps both. The chat does not get lost when you move between agents.

In the practice that goes with this lesson, you will send four short messages, switch models once mid-conversation, and try one off-list model. Twenty minutes start to finish. That is the foundation for everything else in this track.
