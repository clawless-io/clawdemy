## The call, at a glance

```
POST https://api.anthropic.com/v1/messages

Headers
  x-api-key: $ANTHROPIC_API_KEY
  anthropic-version: 2026-10-21     (as of November 2026; the SDKs set it)
  Content-Type: application/json

Body (required)
  model        precise identifier, e.g. claude-opus-5-5
  max_tokens   output ceiling, integer
  messages     [{role: user | assistant, content: "..."}, ...]
                ends with role: user (model generates next assistant)

Body (optional)
  system       standing instructions (persona, format, constraint)

Removed in API version 2026-10-21 (sending them returns 400)
  temperature, top_p, top_k
```

| --- | --- |

All SDKs auto-read *ANTHROPIC_API_KEY* from the environment. They also pick up a sign-in from the CLI (`ant auth login`), which the quickstart recommends for local development.

## Response shape

```
{
  "model": "claude-opus-5-5",
  "id": "msg_013mHbppMPd2PrVJzGMZPt2D",
  "type": "message",
  "role": "assistant",
  "content": [{ "type": "text", "text": "..." }],
  "stop_reason": "end_turn",
  "stop_sequence": null,
  "stop_details": null,
  "usage": { "input_tokens": 21, "output_tokens": 305 }
}
```

A thinking block can come before the text block on models that think; iterate *content* and handle each block by *type*.

## Stop reasons (check on every response)

| Value | Meaning |
| --- | --- |
| *end_turn* | Model finished naturally (the normal case) |
| *max_tokens* | Truncated; raise the cap or split the request |
| *stop_sequence* | Your custom stop string was generated |
| *tool_use* | Model is requesting a tool call (lesson 4) |
| *refusal* | Model declined the request; *stop_details* says why (lesson 2) |

## Multi-turn pattern (the API is stateless)

```
messages = [
  { role: "user",      content: "Hello, Claude" },
  { role: "assistant", content: "Hello!" },
  { role: "user",      content: "Can you describe LLMs to me?" }
]
```

- API holds NOTHING between calls (by default).
- Your application owns conversation state.
- Roles alternate *user* / *assistant*, ending with *user*.
- Synthesized prior turns are OK (the API does not check).
- Every turn pays for the full prior history as input tokens.

## System parameter (where instructions live)

```
client.messages.create(
    model="claude-opus-5-5",
    max_tokens=1024,
    system="You are a terse code reviewer. Return only the changes...",
    messages=[{ "role": "user", "content": "<diff>" }],
)
```

System text is NOT a message. No role. No alternation. Standing instruction for the whole call.

## Five common pitfalls

| Failure | Recognize by | Fix |
| --- | --- | --- |
| API key not set | Auth error on first call | `export ANTHROPIC_API_KEY='...'`; persist in shell profile |
| Wrong model name | Unknown-model error | Use the precise ID from the Models overview (*claude-opus-5-5*), not "Claude" or "Opus" |
| max-tokens too small | Successful response, *stop_reason: max_tokens* | Raise the cap (thinking counts against it) or split into smaller turns |
| Content read as a string | Works once, breaks when a thinking or tool block comes first | Iterate *response.content* and dispatch on each block's *type* |
| Treating API as stateful | Model "forgets" earlier turns | Send the entire conversation history every call |

## Words to use precisely

- **Endpoint:** the URL the request goes to (`https://api.anthropic.com/v1/messages`).
- **Stateless:** by default the API holds no state between calls; conversation state lives in your application.
- **System parameter:** standing instructions, separate from the *messages* list.
- **Stop reason:** the field telling you why generation ended; check on every response.
