Closes Phase 1 of Track 22. Claude models come in tiers, and the names, prices, and limits change every few months, so the [Models overview](https://platform.claude.com/docs/en/models/overview) is canonical. As of November 2026 the lineup is **Fable 5.2** (`claude-fable-5-2`, above the flagship, for demanding reasoning and long-horizon agentic work; $8 input / $40 output per million tokens), **Opus 5.5** (`claude-opus-5-5`, the flagship and the docs' suggested starting point for most workloads; $4 / $20), **Sonnet 5.5** (`claude-sonnet-5-5`, the balanced tier; $2 / $10), and **Haiku 5.5** (`claude-haiku-5-5`, the fastest and cheapest tier; from $0.10 / $0.50, with higher prices for prompts over 100,000 tokens). All four have a 1M-token context window and 128K max output. Opus 4.8, Opus 4.7, Sonnet 4.6, and Haiku 4.5 are legacy and still available. The pick rule: start where the docs point, then let a held-out evaluation move you down a tier; reach for the top tiers when the task is genuinely hard (complex reasoning, agentic coding); reach for the fastest tier when volume matters and the task is light (classification, routing, inner pipeline steps). The common production pattern is mix-and-match (flagship or balanced model for user-facing work, fastest-tier model for inner classifiers). The model-ID convention has two forms: the 4.6 generation and later use dateless IDs that ARE pinned snapshots (`claude-opus-5-5`, `claude-sonnet-4-6`); older models have a date-suffixed canonical ID (`claude-haiku-4-5-20251001`) and a dateless alias (`claude-haiku-4-5`), and production should use the date-suffixed form on those. The **effort parameter** (`output_config: {effort: "..."}` with values `low`, `medium`, `high`, `xhigh`, `max`) controls token spend per call and affects ALL tokens (text, tool calls, thinking). All five levels work on the four current models; the default is `medium` on Opus 5.5 and Haiku 5.5 and `high` on Fable 5.2, Sonnet 5.5, and the legacy models that support effort. Haiku 4.5 does not support effort. **Adaptive thinking** (`thinking: {type: "adaptive"}`, with effort steering depth) is the recommended mode and the only mode on every current model, which rejects manual mode with a 400 error; on Fable 5.2 and Opus 5.5 it is always on. **Manual extended thinking** (`thinking: {type: "enabled", budget_tokens: N}`) is legacy: deprecated on Sonnet 4.6 and Opus 4.6, rejected on Opus 4.7 and later, and the only mode on Haiku 4.5. Evaluation is the way to actually pick: build a held-out test set, run candidates, pick the cheapest that passes.

## Core ideas

- **Tiers, not a fixed list of names.** Above-flagship, flagship, balanced, fastest and cheapest. As of November 2026: Fable 5.2 ($8/$40), Opus 5.5 ($4/$20), Sonnet 5.5 ($2/$10), Haiku 5.5 (from $0.10/$0.50). All 1M context, 128K max output, reliable knowledge cutoff Jun 2026. Legacy and still available: Opus 4.8 and Opus 4.7 ($5/$25), Sonnet 4.6 ($3/$15), Haiku 4.5 ($1/$5, 200K context). Check the Models overview before you build.
- **Pick rule:** start where the docs point, let evaluation move you down a tier, top tiers for hard tasks, fastest tier for volume-and-light. Mix and match across models inside one application; lesson 8 onward (the agent loop) extends this.
- **Model IDs:** 4.6 generation and later, the dateless ID IS the pinned snapshot (`claude-opus-5-5`, `claude-sonnet-5-5`, `claude-opus-4-8`, `claude-sonnet-4-6`). Older models have a date-suffixed canonical ID (`claude-haiku-4-5-20251001`) and a dateless alias (`claude-haiku-4-5`); production uses the date-suffixed form on those.
- **Effort parameter:** `output_config: {effort: "low" | "medium" | "high" | "xhigh" | "max"}`. Affects all tokens (text + tool calls + thinking). The default differs by model (`medium` on Opus 5.5 and Haiku 5.5, `high` elsewhere), and setting a model's default is the same as omitting the parameter. NOT supported on Haiku 4.5.
- **Starting points (per the Effort docs, November 2026):** Fable 5.2 start at `high`; Opus 5.5 default `medium`, run an effort sweep on your evals; Sonnet 5.5 start at `high`, `medium` for well-specified agentic work, `medium` or `low` for chat; Haiku 5.5 start at `medium`, `low` for chat and simple high-volume requests. When you change models, re-sweep rather than carrying the old setting over.
- **Adaptive thinking** (`thinking: {type: "adaptive"}`) is the recommended mode and the only mode on every current model. Effort controls thinking depth. Always on (cannot be turned off) on Fable 5.2 and Opus 5.5.
- **Manual extended thinking** (`thinking: {type: "enabled", budget_tokens: N}`) is legacy. Rejected with a 400 on Opus 4.7 and later (all current models); deprecated but functional on Sonnet 4.6 and Opus 4.6; the only mode on Haiku 4.5.
- **Cost arithmetic is not exotic.** At November 2026 list prices, 100k daily calls all-Opus 5.5 cost about $800/day; the same workload with a Haiku 5.5 classifier plus Sonnet 5.5 answer is about $286/day, roughly 64 percent cheaper. Model choice and parameter choice both move the dial materially.
- **Evaluation is how you pick.** Build a held-out test set, run candidate models, pick the cheapest one that passes. Vibes-driven model selection is the most common cost leak in production AI applications.

## What changes for you

Before this lesson, you were passing whichever model ID lesson 1 used. After this lesson, model selection is a deliberate decision with a worked cost shape behind it. The single highest-leverage change this week: pick one production feature, build a 5-prompt eval set for it, run both the flagship and the balanced tier against it (Opus 5.5 and Sonnet 5.5 as of November 2026), set effort explicitly so both run at a known level, and compute the cost-per-call for each. If the balanced tier matches the flagship on your eval, the swap cuts that feature's token cost by about half at today's list prices. If the flagship is materially better on a subset, you have a routing question (flagship for hard cases, balanced tier for easy ones) and the mix-and-match pattern lesson 8 onward extends. Phase 2 (lessons 4-7) will give you the tools, MCP, and prompt-caching levers that compound on top of the model-selection choice; Phase 3 the agent loop where model choice and effort compound across steps; Phase 4 the production cost monitoring that surfaces the dollars this lesson's arithmetic predicts.
