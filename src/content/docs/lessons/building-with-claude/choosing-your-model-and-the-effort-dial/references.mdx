## Read this next

- **[Anthropic, "Models overview"](https://platform.claude.com/docs/en/models/overview)**. The canonical model comparison; check it whenever the lineup shifts (prices, context windows, support matrices all live here and update as the model lineup evolves).
- **[Anthropic, "Model IDs and versioning"](https://platform.claude.com/docs/en/about-claude/models/model-ids-and-versions)**. The full convention behind dateless and date-suffixed IDs. Worth a careful read when you ship to production.
- **[Anthropic, "Effort"](https://platform.claude.com/docs/en/build-with-claude/effort)**. The full effort-parameter doc. Includes per-model recommended-starting-points tables that go deeper than the lesson's summary.
- **[Anthropic, "Steering thinking"](https://platform.claude.com/docs/en/build-with-claude/thinking-steering-and-cost)**. Thinking is adaptive: the model decides for each request whether to think and how deeply, and the effort parameter is the primary way to steer that. Covers system-prompt and per-message steering alongside the cost mechanics. Per-model defaults shift as the lineup evolves, so read the current page rather than trusting a version named anywhere else.
- **[Anthropic, "Extended thinking"](https://platform.claude.com/docs/en/build-with-claude/extended-thinking)**. The older manual thinking mode, where you set a thinking budget yourself. The docs mark it legacy: newer models reject it, and it remains the only mode on some older models; the page names which.
- **[Anthropic, "Troubleshooting thinking"](https://platform.claude.com/docs/en/build-with-claude/thinking-troubleshooting)**. The per-model table of which thinking settings each model accepts, its default, and which settings return a 400 error.
- **[Anthropic, "Pricing"](https://platform.claude.com/docs/en/about-claude/pricing)**. Full pricing including Batch API discounts and prompt-caching rates (relevant to lessons 2 and 7 of this track).

## Going deeper

A short, durable list. Each link is a specific next step inside Track 22, not a generic pile.

- **Lesson 4 of this track, "Tool use, the foundation."** Opens Phase 2. The first place the effort dial's "affects ALL tokens" property starts to compound, because tool calls are part of total token spend per response.
- **Lesson 7 of this track, "Prompt caching and context management."** The third cost lever after model choice (this lesson) and the effort dial. With caching, batches (from lesson 2), and the right model + effort, you have four cost dials.
- **Lesson 8 of this track, "From single call to agent loop."** Where model + effort compound across multi-step work; total cost is steps times per-step cost, and effort affects both the step count and the per-step spend.
- **Lesson 11 of this track, "Subagents and Claude Managed Agents."** Where the mix-and-match pattern (a balanced model for the orchestrator, a fastest-tier model for inner subagents) becomes the design.
- **Lesson 12 of this track, "Shipping a Claude application."** Cost monitoring at the org level via the Admin / Usage / Cost APIs; turns the *usage* + *request_id* logging from lesson 2 into cost-per-feature dashboards.

## Where this connects inside the track

The decision that compounds, threaded through later lessons:

- **Lesson 1** (first call): the `model` parameter from lesson 1's request body, now with a proper selection conversation behind it.
- **Lesson 2** (production patterns): the *usage* data lesson 2 logged is what an eval-driven model swap actually saves; the cost arithmetic here is concrete.
- **Lesson 4-5** (tool use): the effort dial affects ALL tokens including tool calls; lower effort in inner loop steps compounds.
- **Lesson 6** (MCP): MCP tool calls are token spend the effort parameter controls; same trade.
- **Lesson 7** (prompt caching): caching reduces the input-token side of the same cost arithmetic this lesson worked out.
- **Lesson 8 onward** (agent loop): model and effort choices compound across multi-step work. A 6-step agent on the flagship at high effort can cost significantly more than the same 6 steps on the balanced tier at medium effort.
- **Lesson 11** (subagents): mix-and-match by step (orchestrator gets a balanced model, leaf subagents get a fastest-tier model) is the design.
- **Lesson 12** (shipping): the cost-per-feature dashboards the *usage* + *request_id* logging supports.
