## Claude model tiers (as of November 2026)

| Tier | Model | Model ID | Input / Output (per MTok) | Context | Max output | Default effort |
| --- | --- | --- | --- | --- | --- | --- |
| Above the flagship | Fable 5.2 | `claude-fable-5-2` | $8 / $40 | 1M tok | 128K tok | `high` |
| Flagship (docs' suggested start for most workloads) | Opus 5.5 | `claude-opus-5-5` | $4 / $20 | 1M tok | 128K tok | `medium` |
| Balanced | Sonnet 5.5 | `claude-sonnet-5-5` | $2 / $10 | 1M tok | 128K tok | `high` |
| Fastest and cheapest | Haiku 5.5 | `claude-haiku-5-5` | $0.10 / $0.50 up to 100K prompt tokens; $0.50 / $2.50 above | 1M tok | 128K tok | `medium` |
| Legacy | Opus 4.8 / Opus 4.7 | `claude-opus-4-8` / `claude-opus-4-7` | $5 / $25 | 1M tok | 128K tok | `high` |

## Pick rule

```
Start where the docs point (the flagship, as of November 2026).
Let a held-out eval move you down a tier.
Top tiers when the task is genuinely hard.
Fastest tier when volume matters and the task is light.
Mix-and-match across models inside one app.
```

## Model ID convention

| Generation | Form | What it is |
| --- | --- | --- |
| 4.6 and later (every current model, plus Opus 4.8, Opus 4.7, Sonnet 4.6, Opus 4.6) | Dateless | IS the pinned snapshot |
| Before 4.6 (Haiku 4.5, Sonnet 4.5, Opus 4.5, Opus 4.1) | Date-suffixed (canonical) | Pinned snapshot |
| Before 4.6, Claude API only | Dateless (alias) | Convenience pointer to the most recent dated snapshot; can re-resolve |

**Production:** use the pinned form. For 4.6 and later that is the dateless ID; before 4.6 that is the date-suffixed ID.

## Effort parameter

```python
client.messages.create(
    model="claude-opus-5-5",
    max_tokens=4096,
    messages=[...],
    output_config={"effort": "high"},  # <-- goes here, not top-level; Opus 5.5 default is "medium"
)
```

| Value | Use case (per the Effort docs) |
| --- | --- |
| `max` | Deepest possible reasoning; no constraint on token spend. All four current models; legacy Opus 4.8 / 4.7 / 4.6, Sonnet 4.6 |
| `xhigh` | Long-horizon coding and agentic work. All four current models; legacy Opus 4.8 / 4.7 |
| `high` | Complex reasoning, difficult coding, agentic tasks. Default on Fable 5.2, Sonnet 5.5, and legacy models |
| `medium` | Balance of speed, cost, and performance. Default on Opus 5.5 and Haiku 5.5 |
| `low` | Speed and lowest cost; simpler tasks, subagents |

**Affects ALL tokens:** text response, tool calls, thinking. At lower effort, fewer tool calls + terser preambles + combined operations.

**Not supported on:** Haiku 4.5.

**Setting a model's default** and not setting the parameter are equivalent. Defaults differ by model, so set effort explicitly when you swap models.

## Starting effort by model (as of November 2026)

| Model | Start with | Notes |
| --- | --- | --- |
| Fable 5.2 | `high` (default) | `xhigh` for hardest long-running coding/agentic work where measured; `max` mainly to measure the ceiling |
| Opus 5.5 | `medium` (default) | Adaptive thinking always on; effort is the main control. Run an effort sweep on your evals |
| Sonnet 5.5 | `high` (default) | Agentic: `medium` for well-specified tasks, `high` for harder ones; chat: `medium` or `low` |
| Haiku 5.5 | `medium` (default) | `low` for chat and simple high-volume; `high` for knowledge work and strict instruction following |
| Opus 4.8 / 4.7 (legacy) | `xhigh` (coding / agentic) or `high` (general) | API default `high` |
| Sonnet 4.6 (legacy) | `medium` | API default `high`; set explicitly |
| Haiku 4.5 (legacy) | N/A (no effort support) | What you get is what the model decides |

## Thinking modes (as of November 2026)

| Model | Thinking types | Default | Rejected with 400 |
| --- | --- | --- | --- |
| Fable 5.2, Opus 5.5 | Adaptive only | Always on | `enabled`, `disabled` |
| Sonnet 5.5 | Adaptive; `between_tools` to turn off up-front thinking | On | `enabled`, `disabled` |
| Haiku 5.5 | Adaptive only | On | `enabled`; `disabled` at `xhigh`/`max` |
| Opus 4.8, Opus 4.7 (legacy) | Adaptive only | Off | `enabled` |
| Sonnet 4.6, Opus 4.6 (legacy) | Adaptive; extended (deprecated) | Off | None |
| Haiku 4.5 (legacy) | Extended only | Off | `adaptive` |

**Adaptive:** `thinking: {type: "adaptive"}` (model decides; effort controls depth).
**Manual (legacy):** `thinking: {type: "enabled", budget_tokens: N}`; `display: "summarized" | "omitted"` controls whether thinking text comes back.

Response includes `thinking` content blocks (with a `signature` field) before `text` blocks when thinking fires.

## Cost shape (worked example, 100k calls/day, November 2026 list prices)

```
Feature: 100k calls/day; classifier (500 in + 20 out tokens),
then answer for 70% (500 in + 300 out).

All-Opus 5.5:    classifier $240 + answer $560 = $800/day
All-Sonnet 5.5:  $120 + $280 = $400/day  (50% cheaper)
Mix (Haiku 5.5 classifier + Sonnet 5.5 answer):
                 $6 + $280 = $286/day  (~64% cheaper than all-Opus)
Output counts assumed to include thinking tokens (billed as output).
```

Model + parameter choice both move the dial materially. Lesson 7 (caching) adds the third lever; lesson 12 turns *usage* logs into dashboards.

## Common pitfalls

| Failure | Recognize by | Fix |
| --- | --- | --- |
| Defaulting to the top tier everywhere | High bill, similar quality on most calls | Eval one tier down on real prompts; swap where they tie |
| Using alias in production | Surprise behavior change after a new snapshot lands | Pin to date-suffixed form on pre-4.6 models |
| Swapping models without setting effort | Cost or quality shifts after the swap | Set effort explicitly; defaults differ by model; rerun the eval |
| Forgetting effort affects tool calls | Loop costs compound mysteriously | Lower effort in inner loop steps; eval the quality trade |
| Manual thinking on Opus 4.7 or later (every current model) | 400 error | Switch to adaptive thinking + effort |
| Mixing models without eval | Silent quality regression on the fastest-tier step | Eval routing decisions; pin per-step model to capability need |
