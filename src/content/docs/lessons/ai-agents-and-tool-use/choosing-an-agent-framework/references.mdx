The practitioner version of this lesson. Its contribution to our framing is the fit-question pattern: it treats choosing between options as a "which fits this scenario" question, not a "which wins" question. MIT-licensed.
- **[Agentic AI Frameworks & AutoGen / Building a Multimodal Knowledge Assistant (Berkeley CS294, Lecture 3)](https://www.youtube.com/watch?v=OOdtmCMSOo4)**. Chi Wang on AutoGen and Jerry Liu on LlamaIndex, the framework creators presenting their own designs. The fastest way to hear, firsthand, what each framework is built for.

## The frameworks named here

Each project's own documentation, as a primary source for what it is built for. Listed by category, not by preference.

- **[Microsoft Agent Framework](https://github.com/microsoft/agent-framework)** (orchestration / multi-agent). Microsoft's current framework for coordinating one or more agents and multi-agent conversations; positioned as the enterprise-ready successor to AutoGen.
- **[AutoGen](https://github.com/microsoft/autogen)** (orchestration / multi-agent; maintenance mode). The predecessor to Microsoft Agent Framework. Per its own README, AutoGen is now in maintenance mode (no new features, community-managed), and new projects should start on MAF; kept here for reference and for projects already on it.
- **[LlamaIndex](https://www.llamaindex.ai/)** (retrieval-first). A data framework that treats retrieval over your own documents as a first-class primitive.
- **[LangGraph](https://www.langchain.com/langgraph)** (graph / state-machine). A framework for expressing an agent's control flow as an explicit graph of steps and transitions.
